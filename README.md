# 图像生成实验室

使用自定义中转 API 的图像生成与编辑工具。管理员开通账号，并在管理后台统一配置 Base URL、Token 和模型名称映射；用户登录后在自己的私有空间持续创作、选择旧版本续改，或直接在图片上批注修改要求。

本文说明当前开发分支的账号与批注功能，生产是否已发布需另行核对。实施、测试和待验收状态见 [集成交接](docs/implementation/spec-06-integration-handoff.md)。

## 功能特色

- **账号与用户管理**：管理员直接开户、禁用、恢复和重置密码；用户首次登录必须改密，没有公开注册或邮件邀请。
- **统一 API 配置**：管理员在后台“模型设置”中维护一套 Base URL、Token 和接口配置，启用的登录用户共用模型目录；Token 加密保存在服务端。
- **模型由中转提供**：显式读取模型列表，也可在设置中手动填写模型 ID；不依赖内置模型名单。
- **自由设置模型名称**：生成界面只展示自定义名称；映射可新增、删除、排序、改名或更换模型，重新读取列表不会覆盖已有映射。
- **两种兼容接口**：Images 图片生成 / 编辑，或 Chat Completions 多模态生图。
- **持续创作**：每项创作独立保存草稿、参考图和版本历史；支持新建、切换、重命名。当前展示的成功图片自动成为下一次修改的基准，已保存的版本可跨设备恢复。
- **图片批注**：在选中版本上画框、自由圈选或涂抹，在选区浮框逐条说明；主对话框同步显示编号引用，一次发送全部批注，历史保留原图、说明与新版本来源。
- **文字生成图像与参考图编辑**：首次生成最多两张参考图；修改已有版本时自动带上基准图，并可添加一张补充参考图。提交的单张图片不超过 10 MB。
- **私有图片与历史记录**：账号、创作、任务和成功版本元数据存入本项目 PostgreSQL；已提交图片、文档、批注辅助图和任务清单只写私有 COS，应用服务器不落盘。本浏览器按账号隔离保存未提交草稿和文件，服务端已保存内容仍以远端记录为准。
- 简体中文界面，使用项目内置的思源黑体资源显示中文。

## 本地开发配置

使用 `.node-version` 指定的 Node 22.22.1 和 pnpm 10.28.2。`pnpm-lock.yaml` 是依赖锁文件，不混用 npm 锁文件。

账号版需要本项目专用数据库、认证配置与首次管理员；本地隔离夹具、运行/迁移身份和初始化方法见 [数据库开发说明](docs/operations/database-development.md)。应用只持有运行身份，不能使用其他项目数据库或将迁移凭据放进应用进程。当前数据库与制品契约以 `deploy/release-policy.json` 和 [发布手册](docs/operations/release-runbook.md) 为准。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

准备好本地数据库与 `BETTER_AUTH_URL=http://localhost:3000`、`BETTER_AUTH_SECRET` 后，浏览器访问 `http://localhost:3000` 并登录。使用真实存储/模型还需私有 COS 配置、`PROVIDER_CONFIG_KEY` 和后台模型设置；没有配置时不会回退到匿名模式。自动化验收使用专用本机数据库、内存 COS 与模拟模型，不需要云端凭据或收费调用。

## 登录与 API 设置

管理员通过后台“用户管理”开通普通账号，一次性临时密码只在成功响应中显示，24 小时内首次登录后须改密。改密成功后重新登录；临时密码丢失、过期或已兑换但未完成改密时联系管理员重置。禁用或重置会撤销旧会话，恢复账号不会恢复这些会话。

模型设置由管理员维护：

1. 进入管理后台的 **模型设置**（`/admin/models`），打开 **API 设置**。
2. 填写中转提供的完整 HTTPS **Base URL**，例如 `https://relay.example/v1`。应用保留该前缀，不自动补 `/v1`。
3. 填写 **Token**，按中转文档选择 **Images** 或 **Chat Completions** 接口。
4. 点击 **同步模型**，再添加模型映射：填写显示名称，并从列表选择对应的实际模型；中转未提供列表时，可在映射中手动填写模型 ID。
5. 明确保存配置。普通用户在生成界面选择显示名称并提交提示词；也可以上传 TXT、MD、CSV、JSON、HTML、XML、PDF 或 DOCX 文档，作为本轮背景上下文。首版完成后输入修改要求，选中的成功图片用于下一轮修改。

配置和映射由服务端保存。Token 使用独立 `PROVIDER_CONFIG_KEY` 加密，重新打开设置不会回显；同一地址留空可保留原 Token，更换地址必须重新输入 Token。同步使用当前草稿但不保存全局配置，取消不保存，保存失败保留输入；配置冲突或结果不明时先重新载入核对，不自动重发。

普通用户不填写 Token，也不能通过旧接口覆盖后台配置。账号版不读取、上传或自动删除旧浏览器 API 配置与匿名历史，新账号从空白空间开始。本地和生产是不同环境，配置与数据不会自动迁移；秘密保管要求见 [模型配置保管与恢复](docs/operations/provider-configuration.md)。

读取模型使用中转的 `/models` 接口；列表中可能包含文本模型。读取成功不能证明某个模型支持生图，模型 ID、接口类型和支持的参数仍须以中转说明为准。

### 模型名称与映射

每条映射由自定义显示名称和实际模型 ID 组成。例如，可以添加“极致”和“均衡”两条，再分别选择你希望使用的模型。这些名称只是示例；应用不预设固定档位，也不会自动绑定或判断模型的高低。

管理员在 API 设置中可新增、删除、调整顺序、改名或更换对应模型。生成界面只显示自定义名称，服务端在受理时解析并固定实际配置；历史任务不随之后的映射变化而改写。已选映射被删除时需明确重新选择，不自动换到其他模型。

重新读取模型只更新可选列表，保留已有映射及其顺序。若已映射模型未出现在最近读取的列表中，设置里会提示检查，不会自动替换或删除；确认中转仍支持该 ID 后，仍可保留并使用。

## 持续创作流程

1. 点击 **新建创作**，输入画面描述，按需添加参考图，点击 **生成图片**。
2. 首版完成后，当前大图成为修改基准。填写本轮修改要求，点击 **修改 V1**；按钮中的版本号始终指向所选的基准图。
3. 每次成功生成都会保存为新版本。若要从旧版本继续，在 **创作历史** 中选中它，再提交修改要求；新版本保留其来源关系，已有版本不会被覆盖。
4. 通过 **我的创作** 新建、切换或重命名。各项创作有独立的草稿、参考图与历史，切换不会把另一项创作的图片带入本轮请求。

一项创作生成期间可以切换到其他创作继续编辑草稿；该项创作的输入和版本选择暂时锁定，已完成的基准图仍可查看，新调用仍受服务端并发限制。生成失败或停止等待时保留原图和本轮草稿。遇到“结果未知”先查询任务状态，遇到“保存未完成”使用补保存；补保存只核对并保存已有结果，不重新调用模型。不要把断线当作未计费后立即重新生成。“清空输入”只清除当前输入，不删除成功版本。

修改请求会提交当前基准图，帮助模型延续画面；生成式编辑仍可能改变未要求修改的细节，不保证像素完全不变。

登录同一应用账号后，更换设备可恢复服务端已保存的创作、版本、提交要求与来源。未提交的文字、参考图、文档和批注草稿只在同设备按账号/创作/基础版本恢复，不跨设备同步；本地缓存不能替代服务端成功记录。清除站点数据会移除本机草稿，不会删除远端版本或 COS 对象；退出或切换账号后不会显示上一账号的私有内容。管理员管理账号的权限不包含读取他人作品。

### 图片批注式修改

1. 选中一张成功图片，确认当前“基于 Vn”，进入区域批注。使用 **矩形**、**自由圈选** 或 **涂抹** 标出要修改的位置；也可用键盘添加中心区域并移动、调整大小。
2. 在选区上方的浮框输入说明。主对话框同步显示相同编号和文字；点击编号可返回区域，编辑、删除和撤销同步作用于同一份草稿。关闭浮框不会发送请求。
3. 检查基础版本和全部说明，可补充整体要求，也可仅提交有效批注。使用主对话框统一发送一次；新版本以所选成功版本为父版本，不覆盖旧图。
4. 在创作历史中查看该轮的基础版本、逐条说明和 **原图批注**。换设备仍可回看已提交快照；切换 V1/V2 时恢复各自草稿，不将旧图坐标自动套到新图。

批注要求管理员先针对已保存的实际连接/接口/模型记录双图输入能力。记录只表明已核对输入契约，真实编辑效果仍需单独验收；更换连接、接口、实际模型或 Token 会使原记录失效。能力未确认、基准失效或元数据加载失败时，界面提示处理原因；元数据可重试。

当前批注提交同时传入原始基准图和编号辅助图，已占满两张图片输入，因此不能再加参考图；含图或无法确认无图的文档也会拒绝，确认纯文字的文档仍可使用。每轮最多 20 处，每条说明最多 500 字，整体要求、批注与文档组合仍受总长度限制。位置表达帮助模型理解要求，不保证只改目标区域或像素精确修改。

## 接口与参数

| 接口模式 | 请求方式 | 图片参数 |
|---------|----------|----------|
| Images | `/images/generations`；有参考图时使用 multipart `/images/edits` | 1:1、3:2、2:3 对应固定尺寸；画质可选自动、低、中、高，中转需支持对应参数 |
| Chat Completions | `/chat/completions`，通过多模态消息提交文字与参考图 | 比例作为提示词建议，实际图片尺寸由中转和模型决定 |

这些路径拼接在填写的 Base URL 后。仅支持上述接口约定，不承诺兼容所有中转或所有模型。选择“自动”画质时，不向 Images 接口额外发送画质参数。不同中转的响应格式或能力差异可能需要单独适配。

生成通过当前页面发起的请求执行。**生成期间请保持网页打开**；可以在应用内切换创作。刷新或关闭页面不会安排新的后台生成，重新打开后会查询已登记任务的状态，结果未知时不自动重新调用模型；已有输出但保存未完成时可补保存。停止等待不能保证中转取消上游任务或免除费用。

模型调用使用管理员保存的共享 Token，费用由对应中转账户承担。本轮验收使用模拟模型；真实网关兼容性和批注效果仍待明确授权后验证。

## 图片保存与部署

应用部署地址为 [image.qintopia.cn](https://image.qintopia.cn)，沿用 Nginx 与 Linux Next.js standalone。此地址不代表当前开发分支已经部署；发布状态须分别核对服务器、版本端点和公网。账号版增加本项目 PostgreSQL，私有 COS 保存图片、文档及任务清单。

对象存储是必需配置。账号任务使用 `image-playground/private/v1/<账号摘要>/<creationId>/<runId>/`，其中 `inputs/document` 保存原始文档，`inputs/reference-1` / `reference-2` 保存图片输入，`outputs/final` 保存输出，`manifest.json` 保存任务清单。批注始终保留原始基准字节，辅助图单独生成并保存；图片及文档只在服务端内存处理，不落盘。PostgreSQL 保存所有者、对象引用、hash、任务/版本关系和已提交批注快照；Token、COS 凭据和原始上游错误不进入任务清单。

调用模型前必须完成服务端受理、输入与任务清单保存，并重新核对会话。只有输出和完成清单存入 COS、成功版本事务提交后才报告保存成功。存储失败不会切换到本地或自动重复生图；已有输出而最终保存未完成时按同一任务补记元数据。存储不可用时不能假称状态已保存。

| 环境变量 | 用途 |
|----------|------|
| `IMAGE_DATABASE_TARGET` / `IMAGE_DATABASE_URL` | 固定目标清单中的 local 或 production，以及本项目运行身份连接；库为 `qintopia_image`，schema 为 `app` |
| `BETTER_AUTH_URL` / `BETTER_AUTH_SECRET` | 应用精确 origin 与至少 32 字符的认证秘密；生产必须 HTTPS |
| `PROVIDER_CONFIG_KEY` | 独立 32 字节随机密钥的标准 base64，用于加密后台 Token；不进入源码或普通日志 |
| `COS_BUCKET` / `COS_REGION` | 本项目私有 COS 桶及地域 |
| `COS_SECRET_ID` / `COS_SECRET_KEY` | 服务端专用、受限读写凭据，不发送给浏览器 |
| `ASSET_ACCESS_SECRET` | 保留既有值，用于兼容与恢复边界；账号版不以旧 HMAC 能力链接代替会话授权 |
| `NEXT_PUBLIC_APP_URL` | 应用地址，用于页面元数据 |

迁移连接 `IMAGE_MIGRATION_DATABASE_URL` 和恢复密钥 `IMAGE_RECOVERY_KEY` 仅交给相应维护进程，不进入应用进程。现存 `COS_DOMAIN` / `CDN_AUTH_KEY` 属于历史配置，账号私有读取不依赖它们；本轮不自动清理既有配置或轮换密钥。完整秘密分离、备份和恢复要求以 [发布和恢复手册](docs/operations/release-runbook.md) 为准。

所有对象以 private ACL 上传。图片 `/api/images/<assetId>` 与文档 `/api/documents/<assetId>` 每次检查有效会话和对象归属，返回私有、禁止缓存的响应，不跳转到 COS/CDN。旧 `/api/assets/...` 能力入口停止服务，匿名生成停止；复制 URL 不会授予其他账号访问权。旧测试对象不自动导入、分配或删除。

图片内容只在请求内存中处理，不创建图片临时文件。Next 图片优化已关闭，避免在 `.next/cache/images` 留存副本；旧本地图片路由、Vercel Blob 和持久 Workflow 执行入口已移除。图片展示、复制、下载和再次编辑通过应用同源图片路由完成，不需要为当前链路启用 CDN 或配置 CDN CORS。

Nginx 部署必须关闭图片请求体缓冲和响应代理缓冲，禁止图片临时文件及响应磁盘缓存，并避免在访问日志中记录完整查询串。修改代理配置时须核验这些约束；代码不落盘不能代替部署检查。浏览器草稿、预览和下载属于用户设备上的数据，不属于应用服务器存储。

既有 HTTPS 方案使用 Let's Encrypt，由 Certbot webroot 为 `image.qintopia.cn` 续签；`certbot.timer` 定期检查，绑定该证书 lineage 的 deploy hook 在续签后重载 Nginx。历史部署记录中已通过续签演练，当时证书到期时间为 **2027 年 1 月 23 日 23:28:13（Asia/Shanghai）**；本轮没有重新核验线上证书。此前图片 CDN 证书同步定时器的停用记录属于历史运维资料。

## 项目基础设施

采用本项目专用的 PR → 版本 PR → Draft Release → 人工 Publish → 私有 COS 制品 → 受限 SSH 部署流程，保留 Next standalone 与现有独立 Node 服务。CI 在 Linux / Node 22.22.1 构建和验证制品，服务器负责校验、双端口切换、排空与恢复。发布文件和用户图片的凭据、前缀与清理范围分离。

Release Please 使用仓库临时令牌，并显式触发版本 PR 的只读检查，无需保存维护者个人 PAT。当前个人私有仓库套餐不支持强制分支保护，CI 与维护者的 PR 约定仍有效；保持现有仓库及可见性。

操作与首次接线见 [发布和恢复手册](docs/operations/release-runbook.md)，仓库约定见 [协作规范](docs/repository-contributing.md)，设计边界见 [基础设施规格](docs/implementation/spec-project-infrastructure.md)。工具安装、版本 PR 合并和正式应用发布分别验收；不能因工具已安装就把尚未 Publish 的版本称为上线。
