# 图像生成实验室

使用自定义中转 API 的图像生成与编辑工具。在页面中配置 Base URL 和 Token，读取模型列表，再将自定义显示名称映射到实际模型。无需应用账号，也无需数据库。

## 功能特色

- **可更换 API 配置**：Base URL、Token 和生图接口均在页面顶部的“API 设置”中修改。
- **模型由中转提供**：显式读取模型列表，也可在设置中手动填写模型 ID；不依赖内置模型名单。
- **自由设置模型名称**：生成界面只展示自定义名称；映射可新增、删除、排序、改名或更换模型，重新读取列表不会覆盖已有映射。
- **两种兼容接口**：Images 图片生成 / 编辑，或 Chat Completions 多模态生图。
- **持续创作**：每项创作独立保存草稿、参考图和版本历史；支持新建、切换、重命名。当前展示的成功图片自动成为下一次修改的基准。
- **文字生成图像与参考图编辑**：首次生成最多两张参考图；修改已有版本时自动带上基准图，并可添加一张补充参考图。提交的单张图片不超过 10 MB。
- **图片与历史记录**：提交的参考图、各轮结果和任务清单只写入私有腾讯云 COS，应用服务器不落盘。创作信息、草稿、参考图文件和历史引用保存在本浏览器的 IndexedDB，不含 API Token。
- 简体中文界面，使用项目内置的思源黑体资源显示中文。

## 本地开发配置

在项目目录中使用 pnpm 安装依赖并启动。`pnpm-lock.yaml` 是当前依赖锁文件；旧 `package-lock.json` 与项目依赖不一致，不应使用 `npm ci`。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

浏览器访问 `http://localhost:3000`。查看界面不需要配置 API 凭据；生成图片前按下一节填写自己的中转配置。

## API 设置

1. 打开页面顶部的 **API 设置**。
2. 填写中转提供的完整 HTTPS **Base URL**，例如 `https://relay.example/v1`。应用保留该前缀，不自动补 `/v1`。
3. 填写 **Token**，按中转文档选择 **Images** 或 **Chat Completions** 接口。
4. 点击 **同步模型**，再添加模型映射：填写显示名称，并从列表选择对应的实际模型；中转未提供列表时，可在映射中手动填写模型 ID。
5. 保存配置，在生成界面选择显示名称并提交提示词；首版完成后直接输入修改要求，当前图片会自动用于下一轮修改。

API 配置、Token 与模型映射仅保存在当前标签页的 sessionStorage。刷新后可恢复；关闭标签页后重新打开时可能需要重新填写。它们不会写入应用源码，也不通过环境变量固定某一家中转。

浏览器存储按来源（协议、域名、端口）隔离。首次从本地预览切换到 `https://image.qintopia.cn` 时，需要在正式应用中重新填写 API 配置和模型映射；本地预览的配置与历史记录不会自动迁移。

读取模型使用中转的 `/models` 接口；列表中可能包含文本模型。读取成功不能证明某个模型支持生图，模型 ID、接口类型和支持的参数仍须以中转说明为准。

### 模型名称与映射

每条映射由自定义显示名称和实际模型 ID 组成。例如，可以添加“极致”和“均衡”两条，再分别选择你希望使用的模型。这些名称只是示例；应用不预设固定档位，也不会自动绑定或判断模型的高低。

在 API 设置中可新增、删除、调整顺序、改名或更换对应模型。生成界面只显示自定义名称，实际调用使用对应的模型 ID。

重新读取模型只更新可选列表，保留已有映射及其顺序。若已映射模型未出现在最近读取的列表中，设置里会提示检查，不会自动替换或删除；确认中转仍支持该 ID 后，仍可保留并使用。

## 持续创作流程

1. 点击 **新建创作**，输入画面描述，按需添加参考图，点击 **生成图片**。
2. 首版完成后，当前大图成为修改基准。填写本轮修改要求，点击 **修改 V1**；按钮中的版本号始终指向所选的基准图。
3. 每次成功生成都会保存为新版本。若要从旧版本继续，在 **创作历史** 中选中它，再提交修改要求；新版本保留其来源关系，已有版本不会被覆盖。
4. 通过 **我的创作** 新建、切换或重命名。各项创作有独立的草稿、参考图与历史，切换不会把另一项创作的图片带入本轮请求。

一项创作生成期间可以切换到其他创作继续工作；该项创作的输入和版本选择暂时锁定，已完成的基准图仍可查看。生成失败或取消时，保留原图和本轮草稿，供检查后手动重试。“清空输入”只清除当前草稿和补充参考图，不删除已有版本。当前创作管理仅提供新建、切换和重命名。

修改请求会提交当前基准图，帮助模型延续画面；生成式编辑仍可能改变未要求修改的细节，不保证像素完全不变。

创作元数据、草稿、未提交的参考图文件与历史引用保存在当前浏览器的 IndexedDB 中，不包含 API Token。刷新后可恢复已保存的创作，但更换设备、浏览器或域名不会自动同步；清除浏览器站点数据会移除这些本地记录，不会删除 COS 对象。API 配置和 Token 仍单独保存在当前标签页的 sessionStorage。

## 接口与参数

| 接口模式 | 请求方式 | 图片参数 |
|---------|----------|----------|
| Images | `/images/generations`；有参考图时使用 multipart `/images/edits` | 1:1、3:2、2:3 对应固定尺寸；画质可选自动、低、中、高，中转需支持对应参数 |
| Chat Completions | `/chat/completions`，通过多模态消息提交文字与参考图 | 比例作为提示词建议，实际图片尺寸由中转和模型决定 |

这些路径拼接在填写的 Base URL 后。仅支持上述接口约定，不承诺兼容所有中转或所有模型。选择“自动”画质时，不向 Images 接口额外发送画质参数。不同中转的响应格式或能力差异可能需要单独适配。

生成通过当前页面发起的请求执行。**生成期间请保持网页打开**；可以在应用内切换创作，但刷新或关闭页面后，未完成请求不会自动恢复。重新打开页面后可检查状态并手动重试。取消操作会停止本页等待及连接，但不能保证中转取消上游任务或免除费用。

模型调用使用页面所配置的 Token，费用由对应中转账户承担。目前尚未使用真实中转凭据完成生图验收。

## 图片保存与部署

正式应用地址为 `https://image.qintopia.cn`，域名通过 A 记录直连云服务器上的 Nginx，由 Linux 上的 Next.js standalone 应用提供服务。私有腾讯云 COS 继续保存参考图、结果图及任务记录。

对象存储是必需配置。每次任务在 `image-playground/runs/<uuid>/` 下保存 `inputs/reference-1.*`、`outputs/final.*` 和 `manifest.json`。每轮使用的基准图、补充参考图及生成结果均写入私有 COS；中间版本和最终采用的版本使用相同的保存方式。任务清单包含原始提示词、创作与版本标识、基准版本来源关系（lineage）、白名单元数据、对象键及校验哈希。API Token、COS 凭据和原始上游错误不会写入任务记录。

调用收费模型前必须先成功写入任务记录。存储失败时不会切换到本地或其他存储，也不会自动重复生图。失败/取消记录会尽力写回 COS；对象存储不可用时不能保证该状态更新成功。

| 环境变量 | 用途 |
|----------|------|
| `COS_BUCKET` | 私有 COS 存储桶，当前使用 `qintopia-image-1305166808` |
| `COS_REGION` | COS 地域，当前使用 `ap-shanghai` |
| `COS_SECRET_ID` / `COS_SECRET_KEY` | 服务端专用、受限读写凭据，不发送给浏览器 |
| `COS_DOMAIN` | 兼容字段：当前配置读取仍要求有效 HTTPS 根域名，保留 `https://image.qintopia.cn`；不用于当前图片响应路径 |
| `CDN_AUTH_KEY` | 兼容字段：当前配置读取仍要求至少 16 字符，保留已有值；当前图片响应不使用 CDN URL 鉴权 |
| `ASSET_ACCESS_SECRET` | 至少 32 字符的服务端 HMAC 密钥，用于稳定的逐对象访问凭据 |
| `NEXT_PUBLIC_APP_URL` | 应用地址，正式环境为 `https://image.qintopia.cn`，用于页面元数据和分享链接 |

所有对象以 private ACL 上传。历史记录保存 `/api/assets/...` 稳定能力链接；应用校验 HMAC 后，从 COS 读取图片到请求内存，再以 HTTP 200 直接返回图片字节。该访问路径不跳转到短期 CDN 签名 URL。此路由只允许限定目录内的图片对象，不能访问 manifest 或任意对象键。能力链接相当于该图片的访问权限，分享时需留意；更换 `ASSET_ACCESS_SECRET` 会使原有能力链接失效。

图片内容只在请求内存中处理，不创建图片临时文件。Next 图片优化已关闭，避免在 `.next/cache/images` 留存副本；旧本地图片路由、Vercel Blob 和持久 Workflow 执行入口已移除。图片展示、复制、下载和再次编辑通过应用同源图片路由完成，不需要为当前链路启用 CDN 或配置 CDN CORS。

当前 Nginx 部署已关闭请求体缓冲和响应代理缓冲，禁止请求体临时文件及响应磁盘缓存，并避免在访问日志中记录完整查询串。后续修改代理配置时须保留这些约束；代码层面不落盘不能代替部署检查。浏览器草稿、预览和下载属于用户设备上的数据，不属于应用服务器存储。

HTTPS 使用 Let's Encrypt 证书，由 Certbot webroot 为 `image.qintopia.cn` 续签。`certbot.timer` 定期检查，绑定该证书 lineage 的 deploy hook 在续签后重载 Nginx。本次部署已通过真实续签演练；当前证书到期时间为 **2027 年 1 月 23 日 23:28:13（Asia/Shanghai）**。此前仅服务于图片 CDN 的证书同步定时器已停用。
