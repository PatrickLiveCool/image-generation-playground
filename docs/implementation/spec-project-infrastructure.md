# 图像应用基础设施

基于已上线应用基线 `b0790ef270de110ed5a8ce1eb4d15058716ee939`，参考 Green PMS 主线 `7fd9920d21d4319c3311bb784c230b4da22b4c83` 的交付契约。默认分支保持 `master`，包管理器使用 pnpm，生产运行方式保持 Linux x64 / Node 22 / Next standalone / systemd。

## 交付流程

业务 PR 和版本 PR 均经过 PR 格式、应用测试、类型检查、生产构建及发布工具测试。Release Please 只生成版本 PR 和 Draft Release；人工 Publish 正式 Release 是应用部署入口。生产 Environment 不额外设置 reviewer 或等待时间。工作流手动重试必须核实对应 Release 已正式发布。

本次基础设施安装只配置工具、权限和 GitHub 环境，收编当前运行态；不以安装工具代替发布应用，也不自动合并或发布版本。

## 制品与隔离

CI 在 Linux 构建自包含 standalone，绑定严格语义版本、完整 Git SHA、平台与 SHA-256，包含应用静态资源、版本元数据及 SBOM。归档不包含配置密钥、用户产出、私有操作记录或本机依赖目录。服务器验证后解包，不再构建源码。

发布制品使用现有私有桶的 `qintopia-image/releases/`。应用运行身份只可访问 `image-playground/*`；发布上传、读取和清理权限单独授权。桶当前未启用 versioning，本轮不改变此设置；上传必须禁止覆盖，回读校验，并拒绝部分上传、身份冲突或未知对象。

## 部署与恢复

日常入口为专用 SSH 用户与 forced command，root wrapper 二次验证命令和固定对象身份。TAT 保留给首次安装和救援。服务器工具 root 所有，不执行仓库路径或传入 shell。

4400/4401 交替启动固定 release 路径，切换前持久化意图和恢复记录。先验证本地 health/version，再修改本站点 Nginx 回源、验证 HTTPS 版本，最后等待旧 worker 与连接排空；未排空不强停，也不复用被占用的备用端口。失败恢复旧入口，未知结果先查询原事务。锁覆盖运行态切换、成功回执和对应发布标记。

`/api/version` 从归档内的 `release.json` 读取身份；生产缺失或无效元数据返回 503，不以环境标签假充版本。`/api/health` 只检查元数据和本地配置，不收费、不写 COS。旧时间戳版本明确记录为 legacy，只读收编，不编造 Git 身份。

保留旧版本的应用静态 chunk，供尚未刷新的标签页使用。静态资源与用户图片严格分离，用户图片仍只在 COS；既有 HMAC 密钥、应用环境、Certbot、DNS 和其他站点保持原样。

## 回退与清理

没有服务端数据库，但浏览器 workspace schema 与图片能力链接格式仍是回退边界。只有兼容且已验证成功的版本可成为显式回退目标；失败发布仍应能恢复已记录的 legacy 入口。

清理默认预览，人工选择 apply；本轮不启用定时删除。保护 current、previous、在途事务、运行中服务、恢复引用及至少最近五个成功版本。清理只作用于本项目发布制品，永远不进入用户图片前缀、证书或配置目录。

## 验收边界

分别记录本地源码测试、GitHub CI、制品验证、受限 SSH/root 工具安装、无副作用 status、应用发布和公网验收。工具安装通过不表示新版本已发布；模拟接口和合成图片通过不表示真实模型的编辑保真度通过。
