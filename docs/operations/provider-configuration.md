# 模型配置保管与恢复

管理员在 `/admin/models` 维护一套连接与显示名称映射。普通账号仅获取映射 ID、显示名称和比例；保存和读取不触发模型请求，同步仅请求模型列表。

`PROVIDER_CONFIG_KEY` 是独立的 32 字节随机密钥，以标准 base64 注入服务端。密钥不写入普通数据库转储、应用制品或 Git；由受控秘密管理渠道保管。当前单项目恢复归档可用独立恢复密钥认证加密保存必要应用秘密，受限 FD 恢复与安装要求见 [发布和恢复手册](release-runbook.md#单项目备份与恢复)。不要复用或更换 `ASSET_ACCESS_SECRET`。配置 Token 使用 AES-256-GCM 保存在 `app.provider_settings`，重新打开表单不回显。空 Token 仅在 Base URL 原样一致时保留旧值。

恢复必须配对使用同一时间范围的项目数据库与配置密钥：先核验目标是本项目 `qintopia_image/app` 和受限维护身份，再恢复配套密钥，在隔离环境验证密文可解密且管理员/普通用户响应不包含 Token；恢复配置无需调用真实模型。当前集成测试用合成密钥和密文覆盖缺密钥、错误密钥、损坏密文以及恢复原值。

若密钥缺失或密文损坏，应用拒绝读取和覆盖配置。先核对部署秘密注入与配套备份，不能用输入新 Token 绕过故障。原密钥确实丢失且无可用备份时，旧 Token 无法恢复；保留故障证据后，由维护者另行审阅、授权仅针对本项目配置的重建，再由管理员填写新 Token。首版没有自动清空或重置入口，不提供通用删表操作。备份、恢复工具已实现并完成本地隔离演练，见 [阶段 4 验证](../implementation/spec-04-account-release-recovery.md)；生产安装、秘密接线与恢复演练尚未执行，不因本地通过获得生产操作授权。

基本调用保护默认全局 2 并发、每用户 1 并发、每分钟 6 次，上限分别为 8、全局并发值及 60。以降低共享 Token 的意外并发消耗为目的，不构成供应商费用预算。请求 ID 与指纹永久绑定；结果未知保留固定 300 秒占位，超时释放占位也不允许同请求再次调用模型。

测试套件共用固定的合成 PostgreSQL 夹具，必须串行执行数据库、账号、配置、受理和 HTTP 测试，不与浏览器验收同时清理。所有清理先核验容器、数据库标记和合成账号清单。生产、收费模型效果、部署与人工接受分别留待对应授权及验收。
