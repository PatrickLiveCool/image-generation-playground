# 图像生成实验室：一页审阅重点

更新：2026-10-29。以下是已收敛的产品范围；功能尚未开发，数据库与权限已准备。

## 你只需看这四件事

| 功能 | 做完后怎样使用 |
| --- | --- |
| 账号 | 你在管理后台开账号、禁用或重置；用户用临时密码登录后先改密。首版不做邮件邀请或公开注册。 |
| **模型设置** | **现有 API 设置和名称映射搬到管理后台，操作方式保持。** 你设置一次，启用的登录用户共用这份模型列表；普通用户继续只选显示名称。 |
| 我的创作 | 用户登录后只看到自己的图片和历史，换设备可恢复已保存版本；仍可从任意成功版本继续修改，失败保留原图和草稿。 |
| 图片批注编辑 | 选基础版本并画框／圈选／涂抹 → **选区上方弹出批注框，输入时主对话框同步出现编号引用和说明** → 多处批注与整体要求统一发送 → 得到新版本。点击引用可定位并编辑区域，历史保留这一轮的原图、批注和结果。 |

## 模型设置：与你现在使用的方式一致

**Base URL ＋ Token ＋ 接口类型 → 同步模型或手填 ID → 编辑名称映射与顺序 → 保存。**

- 仍然只有一套连接配置，接口仍是 Images / Chat Completions。
- 映射仍可新增、删除、改名、换实际模型和上下排序；多个不同名称可对应同一模型。
- 重新同步不覆盖映射；缺席模型只提醒，失败仍可手填；取消不保存。
- 同步可试用尚未保存的草稿配置，只有点击保存才更新全局设置。
- 已保存 Token 改为由服务端保管，重新打开不回显明文；可以输入新 Token 替换。更换 Base URL 需重新输入相应 Token，避免把已有秘密静默发往新地址。

你需要留意的实际变化只有：**设置入口和编辑权限归管理员，保存结果供大家共用。** 前台生成、参考图、文档输入与版本续改沿用现在的体验。

## 刚确认的图片版 annotation

**图上就地输入 → 主对话框同步汇总 → 一次发送。** 例如框住标题后，在选框上方输入“标题放大”，主对话框立即出现 `① 标题放大`；还可圈第二处写 `② 衣服改为红色`，补充整体要求后一起提交。浮动框与主输入框引用同一条批注，编辑或删除会同步；切换图片或基础版本不会串用批注。

## 奥卡姆剃刀复核结果

已从首版移出：多供应商资源列表、独立模型启停平台、按用户分配模型、日/月额度账本和配额管理页面。现有代码没有这些概念，搬迁设置不需要它们。

继续保留：管理员鉴权、Token 加密保管、短时限流/并发保护、防重复调用、私有图片、失败恢复，以及数据库防误操作。这些措施由实现负责，不要求你学习一套新的管理操作。

20 条故事是给开发执行的拆分，**不是 20 个需要你逐条确认的新功能**。详版中的命名、技术选型、迁移脚本和测试命令由实施时核对。

## 两个边界与交付顺序

- **数据边界：** 本项目只使用独立的 `qintopia_image` 数据库。其他应用的表、数据、账号、权限和实例配置不在变更范围内；旧测试图不导入，删除仍需单独授权。
- **效果边界：** 标注位置和文字必须正确传给模型，但不能保证模型只改选中像素。真实效果需你看样例验收，收费调用前单独确认。

先交付账号、原设置后台化和私有创作空间，再交付图片批注编辑。批注接口的资料/合成请求验证可在模型设置契约明确后提前进行，避免画布做完才发现接口不支持。
