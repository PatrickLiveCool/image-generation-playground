# 图像生成实验室：开发 Epic 与用户故事

**给产品负责人的入口：[一页审阅重点](REVIEW.md)。** 本文是开发执行附件，20 条故事不需要逐条由用户批准。

## 范围与现状

本计划承接用户已满意的 demo：A1 包含账号与用户管理、网页模型后台、个人私有创作空间；A2 包含用户原始设想中的图片批注式对话编辑。A2 排在基础能力之后，属于本计划内明确安排的工作，不是无期限的“以后再做”。

数据库和权限已准备，应用账号/后台/持久化尚未实现。下文全部故事均待开发，数据库已创建不等于账号故事完成。当前架构仍有技术选型与发布接线缺口，本计划先形成可审阅拆分，再做实施就绪检查。

输入采用当前已确认的 PRD、架构、数据库记录与发布约束；用户要求直接完成拆分，沿用已确认范围，不重复进行逐步菜单确认。正式 UX 规格尚不存在，现有 demo 是创作界面的保留基线，新增页面的最小交互在相关故事内明确。

## 需求清单

### 功能需求

- FR-001：管理员直接开户；登录/退出、临时密码首次改密、禁用/恢复及重置；关闭公开注册和邮件邀请。
- FR-002：用户只能访问自己的创作；管理员的账号/模型管理权不自动授予查看其他用户内容的权利。
- FR-003：服务端保存创作、成功版本、来源与任务状态；跨设备恢复；同设备草稿隔离；冲突和重复请求不损坏结果。
- FR-004：保留文字/参考图/文档生成、当前或旧成功版本续改、失败保留和创作隔离；模型由服务端映射解析。
- FR-005：账号从空白开始，不自动导入旧测试历史；不删除旧 COS 对象或本地记录，不轮换既有能力密钥。
- FR-006：图片、文档、下载与编辑输入按账号授权；停止旧 bearer/匿名入口；未授权请求不泄露对象存在性。
- FR-007：将现有单套 API 设置和名称映射原样迁到管理后台；管理员维护，已启用用户共用目录；Token 改由服务端保管。
- FR-008：在选定基础版本上画框、圈选、涂抹，给标记写修改说明；批注草稿绑定账号、创作和基准版本。
- FR-009：使用原始基准图和批注要求进行下一轮编辑；已提交批注、请求与新版本可追溯；不能静默忽略批注或承诺像素精确修改。

FR-008/009 已同步到 PRD v0.6；四个 Epic 共同覆盖本轮完整范围。

### 非功能需求

- NFR-001：最小权限、会话安全、秘密脱敏、SSRF 防护与管理操作审计。
- NFR-002：只操作本项目独立库/schema/账号；图片、文档、派生图与任务清单只存私有 COS，服务端不落盘。
- NFR-003：正式适配数据库迁移和发布；备份/恢复只针对本项目；回退不能重开私有对象的旧访问旁路。
- NFR-004：区分认证、权限、冲突、限流/并发限制、数据库/COS/供应商失败与结果未知；恢复保存不重复调用模型。
- NFR-005：登录、改密、后台、画布批注与错误恢复具备可理解的反馈、键盘路径及必要的空态/加载态。

### 架构与运行约束

- AD-1～AD-14：沿用单体、服务端授权、数据库/COS职责、版本提交、本地隔离、私有图片、秘密管理、发布回退、审计、账号、幂等与供应商网络边界，并补充批注坐标/基准绑定及模型输入追溯。
- 其他应用的表、数据、账号、ACL及实例级参数不可变更；不能为了本项目隔离而修改 Green PMS 或其他旧库的 PUBLIC 权限。
- 实际目标必须核对：指定实例与部署端点、数据库 `qintopia_image`、schema `app`、运行角色 `qintopia_image_app` 或迁移角色 `qintopia_image_migrator`。不匹配立即停止，云管理凭据不进入应用或日常迁移。
- 当前库/schema/普通账号及默认权限已创建，不重复建库或重置密码。业务表按故事需要逐步增加，不提前创建所有未来功能表。
- CI 使用隔离测试数据库、模拟供应商和合成图片，不连接已购共享实例、不使用云凭据或真实业务记录。
- 生产切换、正式 Publish、清理、付费模型效果验收分别受用户授权约束；本轮只有文档产出。

### UX 输入状态

尚无正式 DESIGN.md / EXPERIENCE.md，不把本轮文字验收当作设计已验收。保留现有创作页面和现有组件；新增登录/改密/账号后台/现有 API 设置的后台入口/标注界面的交互草图随对应故事完成，必要时更新 UX 规格。

## 交付与实施约定

所有故事初始状态均为 `backlog`。单条故事包含所需页面、API、数据变更与对应验证，不拆成互相等待的前后端任务。少量技术前置故事用于收敛现有架构缺口，不重复采购、建库或重做 demo。功能表随故事增加。

**所有故事共同完成条件：** 满足本故事验收条件；相应成功/失败/越权路径有验证；使用现有测试基础，补充有风险意义的缺口；PR 留下检查结果与剩余人工验收。完成代码、PR 合并、应用发布和用户验收分别记录。数据库、模型或权限配置缺失时不得回退到匿名模式、旧 Token 或其他项目库。

**数据库硬边界：** 日常运行仅用运行账号；迁移仅用本项目迁移身份。迁移/恢复必须校验连接目标、库名、schema、当前账号，SQL 与制品来源固定为本项目。禁止修改其他应用的表/数据/账号/ACL、执行共享实例整体恢复，禁止向其他库探测性写入。错误目标和超权负面测试使用本地隔离夹具；没有新的明确授权不再连接其他应用生产库。

## Epic 1: 管理员开通账号，用户安全登录

**成果：** 管理员可以维护用户，用户完成首次改密、登录、退出和管理员辅助恢复。只包含此领域必需的技术前置，不依赖 Epic 2/3 才能验收。

### Story 1.1: 收敛账号实现与数据库接入契约

**状态：** backlog · **依赖：** 无 · **类型：** 有限技术验证
**覆盖：** FR-001；NFR-001/002/003；AD-1/2/8/10

作为维护者，我希望先验证认证库和迁移接线能满足已确认流程，以便后续实现沿用同一份契约。

**验收条件：**

- **前提：** 架构仍未锁定认证库与迁移工具；**当：** 进行隔离环境验证；**则：** 产出已核实来源与版本的选择记录，验证用户名登录、管理员建用户、临时密码改密和立即撤销会话，不以包已安装作为可用证据。
- **前提：** 生产独立库与账号已经存在；**当：** 定义接入；**则：** 固定开发/测试/生产的目标清单、运行/迁移凭据分离、schema 与迁移账本位置，不重建生产库、不重置账号密码、不使用 Green PMS 凭据。
- **前提：** 登录有会话与临时密码；**当：** 完成契约；**则：** 明确状态、有效期、撤销与首次管理员初始化路径，记录安全默认值和理由，不建设邮件或开放注册流程。
- **前提：** 验证存在缺口；**当：** 收尾；**则：** 架构写明已定与未定项及证据，未满足事项阻止相关后续故事进入 ready-for-dev；本故事不创建所有业务表。

### Story 1.2: 让本项目迁移和连接拒绝错误数据库

**状态：** backlog · **依赖：** 1.1 · **类型：** 账号交付的基础保障
**覆盖：** NFR-002/003；AD-2/8/11

作为维护者，我希望数据库连接和迁移主动拒绝越界目标，以便开发图像功能时不触碰其他应用。

**验收条件：**

- **前提：** 接入正确的隔离测试库；**当：** 初始化连接与迁移账本；**则：** 运行/迁移使用各自身份，只创建本故事必需的对象，重复迁移不会重复执行已完成版本。
- **前提：** 目标端点、库名、schema、当前账号或迁移目录不符合部署清单；**当：** 尝试运行；**则：** 在执行变更前停止并返回脱敏原因；自动化证明没有 DDL、角色或权限写入被发送到错误目标。
- **前提：** 运行账号访问新建合成表；**当：** 验证默认权限；**则：** 必需 CRUD/序列操作成功，建表、改表、建角色和切换为迁移账号失败；不通过扩大账号权限解决测试失败。
- **前提：** 两个应用端口可能同时运行；**当：** 配置池与超时；**则：** 进程连接上限计入重叠期且不超过本库 20 个连接预算，超时有明确错误，无逐请求无限建连接。
- **前提：** CI 执行；**当：** 运行上述检查；**则：** 使用隔离本地库和合成对象，不需要真实云凭据；运行进程拿不到迁移或腾讯云管理凭据。

### Story 1.3: 首位管理员可以初始化并登录后台

**状态：** backlog · **依赖：** 1.2
**覆盖：** FR-001；NFR-001/005；AD-3/9/10

作为项目维护者，我希望安全初始化首位管理员并登录，以便开始管理账号。

**验收条件：**

- **前提：** 本项目尚无管理员；**当：** 经受控维护入口初始化；**则：** 只创建一次管理员；无公开初始化/注册接口、默认密码或 Git 内凭据，第二次执行不会静默覆盖密码。
- **前提：** 管理员输入正确或错误凭据；**当：** 登录；**则：** 正确凭据建立安全会话，错误凭据使用不泄露账号存在性的反馈；密码哈希、会话 cookie、请求防伪和登录限速经过验证。
- **前提：** 未登录或会话失效；**当：** 直接访问后台页面/API；**则：** 页面引导登录，API 拒绝访问；隐藏按钮不能代替服务端鉴权。
- **前提：** 后台尚无普通用户；**当：** 登录或退出；**则：** 后台显示明确空态，退出撤销会话并清除页面账号内容；键盘可完成流程，错误和加载状态可感知。

### Story 1.4: 管理员创建用户，用户首次登录改密

**状态：** backlog · **依赖：** 1.3
**覆盖：** FR-001；NFR-001/005；AD-3/10

作为管理员，我希望在网页直接开通账号，让被开通者通过一次性临时密码安全开始使用。

**验收条件：**

- **前提：** 管理员处于有效会话；**当：** 创建普通用户；**则：** 检查用户名唯一性并返回一次性临时密码，仅在本次成功响应显示；刷新/查询账号接口不能取回明文。
- **前提：** 临时密码有效；**当：** 用户首次登录；**则：** 只可进入改密和退出流程；直接访问创作、模型和其他受保护 API 仍被拒绝，不能绕过页面改密要求。
- **前提：** 用户成功改密；**当：** 再次用旧临时密码登录或重放兑换；**则：** 失败；新会话进入当前账号空间，过期临时密码说明联系管理员恢复。
- **前提：** 创建请求重复、保存失败或响应结果不明；**当：** 管理员重试；**则：** 不生成重复账号、不意外重置已存在密码，能够核对结果并选择明确的重置操作。
- **前提：** 普通用户或伪造角色调用开户接口；**当：** 请求到达；**则：** 无数据库变更；表单支持键盘、校验错误、提交中和完成反馈。

### Story 1.5: 管理员禁用和重置账号，用户安全退出

**状态：** backlog · **依赖：** 1.4
**覆盖：** FR-001/002；NFR-001/004/005；AD-3/5/9/10

作为管理员，我希望禁用、恢复和重置用户；作为用户，我希望失效会话不会继续使用我的账号。

**验收条件：**

- **前提：** 用户有多个活跃会话；**当：** 管理员禁用或重置密码；**则：** 下次受保护请求即被拒绝，旧会话不再可用；恢复账号不复活旧会话。
- **前提：** 管理员核验身份后发起重置；**当：** 用户使用新临时密码；**则：** 复用首次改密流程，旧密码/临时密码失效，审计仅记操作者、对象和结果。
- **前提：** 操作会导致最后一位可用管理员被移除或禁用；**当：** 提交；**则：** 拒绝并解释恢复风险，不留下无人管理的应用。
- **前提：** 用户退出、切换账号或已在途请求迟到；**当：** 页面收到数据；**则：** 不把旧账号内容呈现给新账号，不复用旧权限缓存；不能承诺已开始的上游模型任务会被免费取消。

**Epic 1 完成标准：** 在隔离环境完成首位管理员 → 开户 → 首次改密 → 登录 → 禁用/重置 → 再登录的全过程；数据库错误目标负面测试通过。现有生产服务不因该 Epic 验收自动切换。

## Epic 2: 将当前 API 设置与模型映射移到管理后台

**成果：** 管理员按现有方式设置一套连接和名称映射，所有启用的登录用户共用目录。复用现有表单和映射编辑器，不建设多供应商资源列表、模型启停体系、逐用户模型分配或额度页面。

### Story 2.1: 搬迁现有 API 设置表单并安全保存

**状态：** backlog · **依赖：** 1.5
**覆盖：** FR-007；NFR-001/004/005；AD-3/7/9/12

作为管理员，我希望在后台沿用当前 API 设置表单，以便统一配置应用而不学习新操作方式。

**验收条件：**

- **前提：** 管理员打开设置；**当：** 编辑；**则：** 仍是一套 Base URL、Token 和 Images / Chat Completions 选项；完整前缀拼接、不硬编码模型和当前校验规则保留，无新增供应商名称/列表步骤。
- **前提：** 设置处于草稿；**当：** 取消或明确保存；**则：** 取消不改全局值，保存成功才生效；保存失败保留输入，不把客户端乐观更新当持久化成功。
- **前提：** 输入新 Token；**当：** 显示/隐藏、保存与再打开；**则：** 新输入只在本次表单短暂可见；服务端加密保存，重开只显示“已配置”；空值保留已存秘密，初次缺失要求填写，掩码不能被存成新 Token。

### Story 4.2: 在基准图上画框、圈选、涂抹并写说明
