- 版本：0.6

- 代码基线：`master@e26a24d`
- 范围：A1 账号、模型后台与私有创作空间；A2 紧随其后交付图片批注式对话编辑

## 1. 定位与决策来源

用户对现有 demo 的生成、编辑、参考图、文档上下文和版本历史体验满意。A1 延续这些能力，增加账号、网页管理后台和可跨设备恢复的创作记录。用户进一步明确：原始设想中的图片批注式对话编辑必须列入本轮完整开发清单，作为第四个 Epic（A2）紧随 A1；A1 可独立交付，A2 不再作为无交付安排的延后项。

本次用户已选择使用已购买的腾讯云 PostgreSQL，并直接开发网页管理端。用户最新澄清：模型设置沿用现有单套连接配置和名称映射方式，只迁移操作入口与权限，不建设新的供应商管理平台。用户同时说明旧图片均为无保留价值的测试数据。现有实例身份、运行中的 Green PMS 连接、应用服务器网络及近期负载已只读核验。用户已授权使用腾讯云 CLI 创建本项目独立数据库和权限；现已创建 `qintopia_image` 及独立运行/迁移账号，权限与实际连接测试通过，应用尚未接入。管理员后台直接开户、首版网页管理后台及统一账号私有图片均已获用户确认。

| 事项 | 当前状态 | 对旧草案的影响 |
| --- | --- | --- |
| 腾讯云 PostgreSQL | 用户已确认；独立库/账号已创建，权限已验证 | 不再比较新的数据库厂商 |
| 网页管理后台 | 用户已选择，纳入 A1；模型设置原样搬后台 | 一套 Base URL/Token/接口类型＋现有名称映射；只有管理员操作 |
| 旧图片价值 | 用户确认均为测试数据，无保留价值 | 可取消历史迁移需求，但不构成删除授权 |
| 管理员直接开账号 | 用户已确认 | 替代先前的邮件邀请注册方案；首版不建设邮件流程 |
| 图片统一账号私有 | 用户已确认，应用待实施 | 停止兼容旧 bearer 链接，并取消匿名生成；不迁移旧测试图 |
| 图片批注式对话编辑 | 用户要求纳入本轮完整开发计划，安排为第四 Epic / A2 | 依赖 A1 的账号、模型映射、私有图片和版本关系，紧随基础能力交付 |

## 2. 当前源码基线

- 无应用账号，也未接入服务端数据库；发布工具仍按 `databaseMode: none` 检查。
- `components/image-combiner/hooks/use-api-settings.ts` 将 Base URL、Token 和模型映射保存在 `localStorage`；`sessionStorage` 仅作为历史配置迁移来源。旧 PRD 对此描述有误。
- 创作元数据、草稿、未提交参考图/文档和历史引用保存在浏览器 IndexedDB。
- 已提交参考图、结果图、文档及任务清单保存在私有 COS；应用服务器仅在请求内存中处理字节。
- 当前图片读取依赖长期 HMAC 能力链接；生成结果和参考图读取尚无账号归属检查。
- 当前支持新建、切换、重命名创作，从选中成功版本继续修改，以及生成失败/取消后保留原图与草稿。
- 当前尚未实现图片几何批注、逐条批注说明或批注请求追溯；这些是 A2 待实现能力。

以上说明实际现状，不表示账号版已经实现。用户满意的创作行为属于回归基线，身份与访问边界按本 PRD 演进。

## 3. 目标与成功证据

1. 管理员能在后台沿用当前 API 设置与映射操作；已启用的登录用户共用这份模型列表，只选显示名称即可创作。
2. 用户登录后能新建、切换、重命名和继续编辑自己的创作，换设备后能恢复成功保存的版本及来源关系。
3. 当前首版生成、参考图/文档输入、旧版本续改、失败保留和创作间隔离继续成立。
4. 用户不能读取或修改其他用户的创作；账号版的图片、参考图和文档读取均受归属检查。
5. 模型 Token 不进入普通用户响应、浏览器工作区或日志；管理员保存凭据后也不能通过读取接口取回明文。
6. 接入数据库和新访问控制后，发布失败可恢复，且不会影响同一数据库实例上的其他项目。
7. 用户可在选定成功版本上画框、圈选或涂抹，并为每条标记填写修改说明；提交后的新版本可追溯到原图、基础版本、标注和本轮说明。自动化证明请求正确携带批注，不把模型能否精确修改局部视为已验证事实。

## 4. 交付范围与依赖

### A1：账号、模型后台与私有创作空间

- 管理员后台直接创建账号、临时密码首次改密、登录、退出、会话过期反馈及管理员辅助重置。
- 管理员与普通用户两种基本权限。管理员管理账号及配置，但默认无权查看其他用户的创作图片。
- 网页管理端复用当前 API 设置：一套 Base URL、Token、接口类型；同步模型或手填 ID；映射新增、删除、改名、换绑、排序，以及取消/保存。普通用户共用管理员保存的映射列表。
- 复用已购腾讯云 PostgreSQL，为本项目建立独立数据库和访问账号并验证隔离权限。
- 用户创作、成功版本、任务记录与 COS 引用的服务端持久化；同设备草稿按账号隔离。
- 服务端保留已登录/启用账号检查、短时限流、并发保护、幂等与冲突反馈；首版不增加用户模型分配表、日/月额度账本或配额管理页面。
- 数据库接入后的发布、迁移、备份恢复和权限回退边界。

### A2：图片批注式对话编辑（第四 Epic，属于本轮计划）

- 在一个已保存成功版本的原图上画框、圈选或涂抹，并为各标记填写、修改和删除说明。
- 批注草稿按账号、创作和基础版本隔离；保留同设备恢复，切换基础版本时不静默复用另一张图的坐标。
- 提交结构化标注与原始基准图；服务端根据明确的模型映射能力携带辅助图、蒙版或可验证的文字坐标表达，不支持时明确拒绝。
- 已提交批注、任务和新版本来源关系持久化，支持回看本轮改动依据并继续从选中的成功版本修改。
- A2 依赖 A1 的身份、供应商映射、私有对象访问和版本持久化。依赖决定开发顺序，不取消 A2 的交付范围。

### 本轮不包含

- 开放注册、社交登录、组织/团队、多级角色、自定义权限系统。
- 多供应商列表、自动路由、独立模型启停系统、逐用户模型分配、日/月额度账本、计费套餐、充值结算和分析报表。
- 跨设备同步未提交草稿、自动合并并发修改、刷新后自动续跑或重发模型请求。
- 多人批注/评论协作、实时画布协同、复杂图层与专业图像编辑器、分享系统。
- 旧测试数据导入、COS 清理或本地数据清除。

管理员 Token 配置界面需要允许管理员输入秘密并经受保护请求提交；“不暴露 Token”指不回显已保存明文、不发送给普通用户、不写浏览器持久存储或日志。

## 5. 用户使用路径

- **管理员准备应用：** 登录管理后台，照当前方式填写 API 设置、同步或手填模型、编辑名称映射并保存；直接创建或启用用户。保存配置本身不发起收费生图。
- **用户创作：** 登录后看到自己的创作和后台统一保存的模型显示名称，使用现有生成/修改流程；新的成功版本保留来源关系。
- **用户换设备：** 登录后恢复已保存创作与成功版本；未提交草稿不承诺跨设备恢复，界面不得把本地未保存内容显示成已同步。
- **用户恢复账号：** 联系管理员；管理员核验身份后设置一次性临时密码，撤销旧会话，用户登录后必须先改密。
- **用户批注修改：** 选择成功版本作为基础版本，在原图上标出要修改的区域，为每条批注写说明，检查后提交；系统显示本次使用的基础版本和批注，成功后保存新版本及来源关系，失败则保留原图和批注草稿。

这些是待实现的验收场景，不是已完成用户测试的记录。

## 6. 功能需求

### FR-001：账号认证与管理

提供登录、退出和会话恢复。由管理员在后台直接开设账号：用户名与临时密码，首次登录强制改密；首版无开放注册、邮件邀请或自助邮件找回。该决定已获用户确认，替代先前邀请注册方案。

验收条件：

- 普通用户不能调用账号创建、禁用、重置或模型配置管理接口。
- 管理员能创建普通用户、禁用/恢复账号和重置密码；禁用及重置立即撤销旧会话。
- 临时密码仅在创建或重置时显示，不可日后查询；使用前必须完成改密。
- 登录失败、会话过期和退出有明确反馈；退出后清除当前页面的账号数据，切换账号不串数据。
- 首个管理员通过受控初始化产生，不在仓库放默认密码，也不开放公众初始化入口。

### FR-002：个人创作归属

每项账号创作、版本、任务记录与对象引用都由服务端确认所属用户。

验收条件：

- 用户只能读取和修改自己的创作；客户端用户 ID、对象路径或 URL 不能授予权限。
- 管理员身份只授予账号与配置管理权，不自动授予查看其他用户图片的权限。
- 同设备草稿、参考图和文档按用户身份隔离，不能被另一个账号自动加载。

### FR-003：持久化与恢复

创作名称、成功版本、版本来源关系和已保存任务记录由服务端持久化；保留同设备草稿恢复，不承诺跨设备草稿同步或在途模型续跑。

验收条件：

- 新会话/设备能恢复已成功保存的创作与版本；本地未同步内容有明确提示。
- 失败、取消及结果未知不会覆盖成功版本；未知状态不自动重发收费请求。
- 重复请求不产生重复模型调用；过期写入返回冲突并保留本地输入，不静默覆盖远端版本。

### FR-004：保持现有创作流程

账号与管理配置接入后，保留文字/参考图/文档生成、当前成功版本作为修改基准、选中旧版本续改和创作隔离。

验收条件：

- 修改必须提交所选原始基准图；无效基准明确失败，不退回文生图。
- 失败或取消后保留原图和本轮草稿；切换创作或账号不会把结果写进另一项创作。
- 普通用户提交模型映射标识，由服务端解析实际模型和配置；不能通过自报 Base URL、Token 或模型 ID 绕过后台权限。

### FR-005：旧本地测试数据处置（保留编号，取消必做导入）

用户已确认旧图片无保留价值且不做历史导入。A1 新账号空间从空白开始，旧浏览器记录不自动归入账号，也不与新空间合并。

验收条件：

- 本轮规格更新不删除 COS 对象、不轮换 `ASSET_ACCESS_SECRET`、不清理浏览器记录。
- 后续若清理旧数据，单独明确对象范围和授权；发布清理不得顺带删除用户图片。

### FR-006：图片和任务记录访问

**用户已确认：** 账号版统一私有访问，不保留旧 bearer 链接兼容；未登录用户只进入登录流程，不生成或读取私有内容。

验收条件：

- 图片查看、下载、参考图/基准图读取、文档读取及生成结果都执行会话与归属检查。
- 新结果不签发旧式长期 bearer 链接；旧路由和旧请求格式不能绕过新对象授权，不能仅增加一个私有 GET 接口。
- 无归属的旧测试对象不自动分配给任何账号；旧访问入口停止提供图片，但不据此删除对象。
- 未授权请求不泄露其他用户对象是否存在；已授权用户的对象缺失可获得可恢复的错误提示。

### FR-007：将现有 API 设置和名称映射移到后台

管理员继续使用当前设置流程：填写 Base URL、Token 和 Images / Chat Completions 接口类型 → 显式同步模型或手填模型 ID → 编辑显示名称与模型映射 → 保存。首版只有一套共享连接配置，所有启用的登录用户使用同一份映射列表；设置权限限于管理员。复用现有表单/映射组件，不新增供应商资源目录或用户模型权限矩阵。

验收条件：

- 保留完整 API 前缀，不自动补 `/v1`；不硬编码供应商、具体模型或档位。
- 映射支持新增、删除、改名、换绑和上下排序；ID 稳定；多个不同显示名可指向同一模型，空值和重复显示名仍按当前规则拒绝保存。
- 同步只更新候选模型列表，不覆盖已有映射；模型缺席仅提示，空列表或同步失败仍允许手填。删除当前选中映射时不自动选择另一个模型；历史任务保留提交时的映射快照。
- 设置先编辑草稿；取消不保存。同步允许使用尚未保存的草稿地址和新输入 Token，不会隐式更新全局配置；保存失败保留草稿。连接变动/关闭窗口中止旧同步，迟到响应不覆盖新草稿。
- 只有管理员能访问配置读写和模型同步接口，普通用户只获取显示名称和映射 ID；仅隐藏前台设置按钮不算完成权限迁移。
- Token 改为服务端加密保存，加密主密钥独立保管；已保存 Token 只返回“已配置”，不回显明文或把掩码当新值。管理员新输入 Token 可短暂显示/隐藏，不进入浏览器长期存储或日志；未输入新值表示保留已有秘密，首次未配置时明确要求填写。
- 同步使用已保存 Token 时由服务端取用；更改 Base URL 后不得静默把已有秘密发送到新地址，需重新输入相应 Token。普通用户请求只提交映射 ID，服务端解析配置；旧客户端 Base URL/Token/实际模型 ID 不得覆盖后台设置。
- 保存与同步模型列表不发起生图。短时限流、平台并发和账号启用检查作为服务端基础保护，不新增配额产品或设置必填流程。

### FR-008：图片批注操作与草稿（A2）

用户在一个已保存成功版本上画框、圈选或涂抹，为每条标记填写修改说明；标记用于表达修改位置，原始基准图保持不变。

验收条件：

- 每条批注有稳定标识、几何类型、坐标/路径与对应文字说明，支持选择、修改、删除以及撤销本轮未提交标注；图上标记与说明列表对应明确。
- 用户创建或选中区域后，默认在选区上方弹出浮动批注输入框；空间不足时调整到可见位置，避免遮住正在输入的文字。输入过程中主对话输入框同步显示同一编号的批注引用与说明摘要，不需要复制粘贴或先单独发送。
- 点击主输入框的批注引用可定位并重新编辑对应选区。浮动框、图上标记和主输入框引用同一条批注；编辑/删除同步，不生成多份独立文本。可以添加多处批注、补充整体要求后统一提交；局部输入和失焦本身不触发生成。
- 批注绑定不可变的 `baseVersionId`、原图对象和原图宽高，坐标以原图为参照；显示缩放或窗口尺寸变化后仍指向同一原图位置。
- 切换账号、创作或基础版本后，草稿按三者隔离；不能把旧基础版本的标注静默套到另一版本。失败/取消后保留当前原图和同设备批注草稿。
- 标注叠加层与原图分开保存；不把带标记的合成图当作唯一编辑基准，也不覆盖成功原图。
- 说明列表和提交/删除等操作有清晰的焦点、键盘和错误反馈；空说明、无效坐标或失效基础版本不能静默提交。

### FR-009：批注编辑提交与追溯（A2）

批注编辑请求必须提交结构化标注、逐条说明和对应原始基准图，并明确怎样把位置信息传给选中的模型映射。几何标注表达用户意图，不承诺模型只改变指定像素。

验收条件：

- 服务端重新校验账号、创作、基础版本和原图归属，核对原图尺寸与坐标范围；不能通过客户端对象地址或版本 ID 引用他人图片。
- 后端依据已验证的映射能力选择辅助标注图、蒙版或可验证的文字坐标表达，并在任务中记录实际采用的方式。原始基准图始终保留在请求中，不能只发送标记后的图。
- 批注能力核验绑定实际供应商地址、接口类型、模型与配置版本；换绑后不得仅凭稳定映射 ID 继承旧能力，须重新核验。仅修改显示名称/排序不改变模型能力。
- 映射不能承载本次批注，或输入数量/尺寸等接口限制无法满足时，在收费调用前明确拒绝并保留草稿；不静默丢弃批注、不回退为无批注生图。
- 已提交的批注快照、逐条说明、基础版本及原图引用、表达方式与任务关联持久化；成功的新版本保留同一创作及父版本关系，历史可回看，后续编辑不会改写已提交快照。

## 7. 非功能与运行边界

- **NFR-001 安全与隐私：** 密码安全存储、会话撤销、请求防伪、登录限制和最小权限不可省略；继续保留 provider URL 的公网校验与 SSRF 防护。记录配置操作审计，但不记录秘密、签名参数或完整上游响应。
- **NFR-002 数据安全：** 数据库优先复用已购实例，使用本项目独立数据库和最小权限账号，隔离迁移身份；不得混用其他项目业务表、共用超级账号或擅自改实例级设置。图片、文档、批注派生图/蒙版和任务清单仍只存私有 COS，服务器不落盘；批注元数据与提交快照遵守同一用户归属。
- **NFR-003 发布与回退：** 当前发布工具不支持数据库迁移，需正式增加迁移、备份恢复和兼容验证，不能修改一个 policy 字段绕开检查。新账号数据必须保留；回退目标不能重新开放旧 bearer/匿名路径读取私有对象，不承诺直接退回无账号 demo。需要时进入维护状态。
- **NFR-004 可观测性：** 区分认证、权限、同步冲突、数据库、COS 和上游失败；使用不含秘密的关联信息。COS 成功与数据库提交之间的部分失败必须可排查和恢复。
- **NFR-005 可访问性：** 登录、改密、管理配置、批注说明与提交操作及错误恢复支持键盘操作，显示明确的加载、空态、错误和权限反馈。
